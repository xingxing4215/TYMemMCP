# 真机验证记录：当前版本小地图除雾链

**验证时间**：2026-11-01
**设备**：192.168.31.139，游戏 `czrxd`，pid 591
**工具**：TYMemMCP v1.0.0（进程内 MCP，21 个工具）
**镜像**：`UpdateScript_500.dll`（热更 DLL，运行时已加载）

---

## 结论

混淆名全部重排，但**结构完全没变**：

```
MDDOAIFGMLM.PHJLMGMJIAJ            static，类型 HDLMCGPFPIL   @ 0x1279a6c80
  └ .KFOGNCNFFDE                   类型 WarFogAgent           @ 0x12f671600
      ├ .currentViewPrefab         类型 GameObject             @ 0x12f518b60
      │   └ get_activeSelf()       = true    ← 雾层当前开启
      └ .fogCamera                 类型 Camera                 @ 0x12f518aa0
```

对照逆向规格里记录的旧版本名字：

| 层级 | 旧版本（ver 981） | 当前版本 | 稳定性 |
|---|---|---|---|
| 静态容器类 | `CINBLKINBLA` | `MDDOAIFGMLM` | ❌ 每版都变 |
| 静态字段 | `HIIILCBEIJG` | `PHJLMGMJIAJ` | ❌ 每版都变 |
| 容器类型 | `GDNBNONMNGB` | `HDLMCGPFPIL` | ❌ 每版都变 |
| **WarFogAgent** | `WarFogAgent` | `WarFogAgent` | ✅ **不变** |
| **currentViewPrefab** | `currentViewPrefab` | `currentViewPrefab` | ✅ **不变** |
| **fogCamera** | `fogCamera` | `fogCamera` | ✅ **不变** |

这正是「版本无关锚点」策略成立的原因：只有内核三个名字稳定，
外面包了几层混淆壳，靠**类型关系**反查就能重建。

## 重建方法（可复用）

### 第 1 步：定位 WarFogAgent 所在镜像

```
il2cpp_find_class  class=WarFogAgent
→ found=true
```

注意：`find_class` 不回报镜像名。用 `list_classes` 逐镜像搜：

```
il2cpp_list_classes  image=UpdateScript_500.dll  regex=WarFog
→ [{"name":"WarFogAgent","ns":""}]
```

### 第 2 步：按类型反查持有者（核心）

```
il2cpp_find_by_field_type  type_name=WarFogAgent  image=UpdateScript_500.dll
→ HDLMCGPFPIL.KFOGNCNFFDE   (instance)
→ IIPIBABAMKM.KFOGNCNFFDE   (instance)
```

两个都是实例字段，不是静态 —— 说明还有一层。

### 第 3 步：继续向上反查，直到出现 static

```
il2cpp_find_by_field_type  type_name=HDLMCGPFPIL  image=UpdateScript_500.dll
→ MDDOAIFGMLM.PHJLMGMJIAJ   (STATIC)   ← 这就是根
```

> 判据：**找 static 的那个**。全静态容器类是所有实例的统一入口。
> 别选 `<>4__this` 这类编译器生成的闭包字段。

### 第 4 步：验证整条链

```
il2cpp_navigate
  class = MDDOAIFGMLM
  image = UpdateScript_500.dll
  root  = {"field":"PHJLMGMJIAJ"}
  path  = [{"field":"KFOGNCNFFDE"}, {"field":"currentViewPrefab"}]
→ object_class=GameObject, address=0x12f518b60
```

`object_class` 字段是关键校验：它读的是对象的**真实类名**，
和预期（GameObject / WarFogAgent / Camera）对不上就说明链走错了。

## 两个 WarFogAgent 持有者的区别

`find_by_field_type` 返回了两个：

| 类 | 字段数 | 特征 |
|---|---|---|
| `HDLMCGPFPIL` | 101 | 有 `visiblePoints` / `visiblePointsOld`（`Dictionary<String, List<Vector3Wrapper>>`）—— **战争迷雾已探索点数据** |
| `IIPIBABAMKM` | 269 | 有 `MiniMapNpcObj` / `CzrMapPlayerItem` 等小地图 UI 元素字典 |

`HDLMCGPFPIL` 才是迷雾本体（`visiblePoints` 直接就是"哪些点被点亮了"）。
`IIPIBABAMKM` 偏向小地图显示层。

除雾走 `currentViewPrefab.SetActive(false)` 即可；
若要更彻底（连数据都不留），可以改 `visiblePoints`。

---

## 除雾的两种做法

### 做法 A：关掉雾层 GameObject（简单，推荐）

```
目标：MDDOAIFGMLM.PHJLMGMJIAJ → KFOGNCNFFDE → currentViewPrefab
动作：SetActive(false)
```

已验证 `get_activeSelf()` 当前返回 `true`，说明雾在渲染。
关掉即可看到全图。

**风险**：游戏 `WarFogAgent.Update` 每帧可能重新 `SetActive(true)`。
若 `one_shot` 不生效，需改成每帧持续写。

### 做法 B：改迷雾数据（彻底）

`HDLMCGPFPIL.visiblePoints` 是 `Dictionary<String, List<Vector3Wrapper>>`。
直接往里面塞全部格点，雾就没得挡了。

**代价**：要构造泛型容器，比切 GameObject 复杂得多，且可能被服务端校验。

## 一句话总结

**换版本后不要去找 `CINBLKINBLA` 这种名字，它必然变了。**
从 `WarFogAgent` 出发，按「谁持有我这个类型的字段」逐层向上，
遇到 `static` 就停 —— 得到的路径在新版本上照样能用。
